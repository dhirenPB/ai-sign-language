1. THE GOAL
-----------
Train a model that maps English text to continuous sign-language pose sequences, using the iSign dataset directly (Exploration-Lab/iSign on
Hugging Face, gated) and the existing ProgressiveTransformersSLP model (BenSaunders27/ProgressiveTransformersSLP, commit
ff8b28cb0817d177f63dfa18c7c322806ee5dd96). The architecture is NOT replaced: 2 encoder + 2 decoder Transformer layers, d=512, 4 heads, ff 2048
(about 15 M parameters without the word-embedding table, 30 M with a 30,000-word vocabulary).
The owner's separate ISL-gloss pipeline (the rest of this git repository: src/isl_gloss, transcript cleaning, web UI ...) is NOT used for the training targets.
The work in this folder was done to make the pre-training stage technically ready for a controlled experiment: correct preprocessing, masks,
data splits, device handling and validation. The six requested fixes are all implemented (section 5).


2. THE DATA
-----------
- iSign_v1.1.csv: columns uid,text. 127,237 rows, no duplicates, no empty text. uid = "<12-hex video id>-<sequence number>" (unpadded, with gaps),
  e.g. 1782bea75c7d-1. video_id = everything before the LAST "-". About 5,900 videos.
- iSign-poses_v1.1_part_aa..ad: ONE split ZIP of .pose files (pose-format, MediaPipe Holistic, 576 landmarks per frame: body 33, face 468,
  left hand 21, right hand 21, world-pose 33). Parts: 48.3 GB x3 + 25.3 GB = 170.2 GB, 127,237 entries, all of them match a CSV row.
  Read them through VirtualConcatFile (isign_pose.py); never join or extract them.
- Header image sizes differ per file: about 83-93% are 300x300, the rest have their own sizes (e.g. 648x720, 664x720, 562x660, 450x396),
  coordinates in that frame's pixels. This is why x/y are normalised PER SEQUENCE (section 4).
- Confidence: 80.3% of the kept landmarks are valid (confidence >= 0.5, not masked, not non-finite); there are no exact-zero-but-confident landmarks.
- Split by video, seed 27, 80/10/10 of sequences: train 101,791 seq / 4,728 videos; val 12,831 / 661; test 12,615 / 669. Decided on the matched
  sequences BEFORE quality filtering so exclusions never move a video.
- Exclusions at conversion time (logged with reasons): too long (> 600 frames, about 2%), too few valid landmarks (< 15%), no valid hand landmark,
  too short (< 2 frames), too many empty frames.
- Review-scale conversion done on Colab (first shards in archive order): train 995 of 1,024, val 249 of 256, test 251 of 256 sequences,
  about 202 frames per sequence, 525 bytes per frame (225 coordinates in float16 + 75 validity flags). The full dataset would be about 13 GB.
- Observed on a 300-sequence training sample: hand wrist to own body wrist median distance 0.057-0.060 (normalised) vs 0.80-0.83 to the opposite
  wrist (left/right ordering and shared coordinate system confirmed); frame-to-frame displacement p50 0.022, p99 0.26, p99.9 0.51, max 2.45, with at
  least one displacement above 0.5 in 170 of 300 sequences (rare single-frame pose-estimator glitches, about 0.1% of displacements; not handled,
  a robust loss or smoothing is an option for later); landmark groups' share of target variance: hands about 54%, pose-hand points 20%, face 17%,
  hips/knees/feet about 0% (they are rarely valid); hand z is small (about +-0.05) but not corrupted.


3. THE FRAME REPRESENTATION (do not change silently)
----------------------------------------------------
- 75 landmarks = 33 body + 21 left hand + 21 right hand = pose-format indices 0:33 and 501:543 (checked against the file header; a different header raises).
- 225 coordinates per frame, landmark-major [x0,y0,z0,x1,y1,z1,...] plus 1 frame counter = 226 values per frame.
- Counter = frame_index / n_frames (first frame 0.0, last (n-1)/n). It is NOT stored; it is regenerated when loading.
- Decoder alignment: input at step t = frame t, target at step t = frame t+1 (counter included); padding is zero.
- Invalid landmarks (low confidence, masked, non-finite, exact raw (0,0,0)) are stored as 0.0 AND flagged in a separate [T,75] validity array.
  The loss uses the flags (and the padded-frame mask), never the coordinate values. No imputation/interpolation; decoder INPUTS contain 0.0 there.
- Normalisation (hash 50878210e1 for the default settings): x -> (x - width/2)/(width/2), y -> (y - height/2)/(height/2) with width/height from each
  pose header (300x300 if missing; identical to (v-150)/150 for 300x300 files); no clamping; z kept in source units (z_mode "keep").
  Reason for "keep": z is not pixel-scale, hand z is simply small, nothing dominates the loss. "scale" mode (per-component scales from a TRAINING sample)
  exists. A small z spread is a WARN, only a z that would dominate the loss (ratio > 10) is a FAIL.
- Stored shards: float16 coordinates (quantisation error checked, about 5e-4 relative).

  PASS on a CUDA device (UNVERIFIED on CPU).
5 Overfit experiment on a fixed training subset (reports the measured outcome, no fixed threshold).

9. KNOWN ISSUES, DECISIONS AND GOTCHAS
--------------------------------------
- The repository's feed-forward layers use a hard-coded dropout of 0.1 (the config's dropout 0.0 does not reach them): training-mode passes are not deterministic.
- Free-running (greedy) decoding is slow (one decoder pass per frame, quadratic): use limited batches; the repository's greedy decoding uses the ground-truth frame
  counters; unconstrained text-only inference (stopping on a predicted counter) is NOT implemented.
- Resume granularity is one epoch. A resumed run keeps the saved vocabulary (src_vocab.txt in the run folder) and refuses a different model/normalisation config.
- Keep the converted shards and the dataset private (licence). Never commit them.
- On Windows the DataLoader uses spawn; classes must stay importable from modules (they are), and scripts need the __main__ guard (pc_run.py has it).
- The model repository's own training.py/data.py/prediction.py still import torchtext and are NOT used.
- Open modelling ideas, not done: mixed precision (a T1000 has no tensor cores, so limited gain), skipping every other frame, a larger batch, robust loss or smoothing
  for the rare keypoint jumps, excluding the redundant pose-hand points 17-22. Landmark selection and frame layout must not change without the owner's decision.
